# LAN 文件传输 v2 · 技术实现文档

> 版本 2.0.0 · PyQt6 6.11 + PyInstaller 6.22
> 产物:`dist/Wlan-Flash-Transfer-V2.app`(macOS onedir)/ `dist/Wlan-Flash-Transfer-V2.exe`(Windows onefile)
> 界面样式参考 TCode GUI(深色开发者工具风格) · 前代 v1(tkinter)位于 `../lan-file-transfer/`,本目录独立

## 一、总体架构

```
main.py                       入口(GUI / --smoke / --screenshot)
lan-transfer-v2.spec          PyInstaller 配置(mac .app / win 单文件 exe,依赖快速失败守卫)
build.sh / build_windows.bat  双平台打包脚本(均含 frozen 冒烟)
assets/                       icon.icns / icon.ico / icon.png(⚡ 闪电,QPainter 绘制,已提交)
shared_files/                 开发态默认共享目录
lan_transfer/
├── __init__.py               __version__ / APP_NAME
├── qrterm.py                 零依赖二维码(编码 + QPixmap 渲染)
├── core/                     核心层(无 Qt 依赖,可独立测试)
│   ├── server.py             TransferServer:可实例化的 HTTP 服务 + 全部 API
│   └── webui.py              HTML_PAGE:布局E 单页 Web UI(桌面/移动自适应,零外部资源)
└── gui/
    ├── theme.py              深色 QSS(tcode 风格)+ 配色常量
    ├── workers.py            Worker(QThread)
    ├── widgets.py            表格 / 徽标 / 等宽字体
    └── main_window.py        主窗口(服务 + 聊天双 Tab / 二维码 / 日志 Dock)
```

分层原则:**core 不 import Qt** —— 服务器的上传/下载/删除/聊天/路径安全
全部可在无界面环境(`--smoke`、脚本、CI)直接验证。

### 与 v1 的核心差异

| | v1 | v2 |
|---|---|---|
| GUI | tkinter(单文件内嵌服务器) | **PyQt6**,tcode 深色风格 |
| 服务状态 | 模块级全局变量(`UPLOAD_DIR`/`server`/…) | **TransferServer 实例**:目录/端口/聊天/回调全实例态,闭包 Handler,支持多实例 |
| 二维码 | 仅网页端 | 桌面**屏上直接显示**(`qrterm` 本地生成,零联网) |
| 路径安全 | 仅取 basename | basename + **resolve 前缀越界双重校验** |
| 自检 | 无 | `--smoke`(起服务→请求接口→停止),打包脚本自动执行 |
| 日志 | tkinter 子线程直写(不安全) | Qt 信号桥回主线程 |

## 二、核心实现

### 2.1 服务核心(`core/server.py`)

`TransferServer(upload_dir, port, bind)` —— 可实例化、线程安全回调:

- `start()/stop()`:`ThreadingHTTPServer`(daemon_threads)跑守护线程;
  绑定结果经 `threading.Event`(`started`)+ `last_error` 通知,GUI 侧 `QTimer` 轮询,
  **无 sleep 竞态**;`stop()` = `shutdown()` + `server_close()` 双保险且吞连接噪音
- `on_log(str)` / `on_chat(dict)`:回调钩子,由 GUI 接到 Qt 信号
- `url` 属性:`http://<lan_ip>:<port>`,IP 经 UDP connect 探测(不发包)
- `list_files()`:目录扫描,按修改时间倒序,供桌面表格与 `/api/files` 共用

**HTTP API**(Handler 为闭包工厂 `_make_handler(state)`,绑定实例状态):

| 路由 | 方法 | 行为 |
|---|---|---|
| `/` | GET | 返回 `HTML_PAGE`,替换 `__LAN_IP__`/`__PORT__` |
| `/api/files` | GET | JSON 文件列表(name/size/modified) |
| `/api/download/<name>` | GET | 流式下载,1MB 分块,`Content-Disposition` 带 `filename*=UTF-8''`(中文兼容);吞 BrokenPipe |
| `/api/upload` | POST | 头 `X-Filename`(**URL 编码**,服务端 `unquote`);按 Content-Length 流式落盘;**先查磁盘剩余空间**,不足拒绝并提示需要/可用大小;失败自动删半截文件 |
| `/api/chat` | POST | 昵称截 20 字、消息截 2000 字、保留最近 200 条;触发 `on_chat` 回调 |
| `/api/chat` | GET | 当前消息列表 |
| `/api/delete/<name>` | DELETE | 删除共享目录内文件 |

**路径安全**(`safe_filename` + `_file_path`):URL 解码 → 跨平台 basename →
`(upload_dir/name).resolve()` 前缀必须落在共享目录内;
`../` 穿越、绝对路径、空名/`.`/`..` 一律 400/404。

**工具函数**:`get_lan_ip()`(UDP connect `10.255.255.255` 探测,失败回退
hostname → 127.0.0.1)、`format_size()`。

### 2.2 Web UI(`core/webui.py`)

`HTML_PAGE`:「布局E」单页应用 —— 深色主题,桌面/移动一套代码自适应:

- **桌面(>980px)**:左右等宽分栏(上传+共享文件 | 聊天室),CSS Grid 等高行,
  两列底部对齐;聊天卡随行拉伸
- **手机(≤980px)**:单列文件优先;聊天收进右下角**悬浮球**(未读数字角标),
  点击滑出全宽 85vh 底部面板;统计格自动排成 2×2
- **共享文件**:排序(最新/名称/大小)、分页(每页 8 个,超出折叠省略号;
  上传完成/切排序自动回第 1 页)、行内三色按钮(蓝下载/灰删除/绿分享)
- **分享**:优先 `navigator.share`(手机系统分享面板),降级复制下载链接(带提示)
- **聊天**:昵称按 UA 识别设备类型自动生成并 localStorage 记忆;
  头像 = 昵称哈希映射 emoji(纯前端,无需后端存储,各端一致);
  自动滚底仅在已位于底部时触发,不干扰翻阅历史
- **兼容性**:不使用可选链(`?.`)等 2020 后语法,`MediaQueryList` 监听做
  `addEventListener/addListener` 双路降级 —— 最低支持 2017 年内核
  (Chrome 55+ / Safari 10.1+)
- **预览模式**:HTML 单独双击打开(占位符未被替换)时自动加载内置演示数据,
  便于离线预览界面;由应用服务打开时走真实 API,演示数据不出现

纯内联 CSS/JS,无 CDN、无外链,断外网可用;占位符 `__LAN_IP__`/`__PORT__`
由 `TransferHandler._serve_index()` 在响应时替换。

### 2.3 二维码(`qrterm.py`)

与野兔 v2 同源(逐字复用):纯标准库 QR 编码器,字节模式、版本 1–10、
纠错 M;zxing-cpp 解码回归全版本通过,V7/V10 与官方库逐格一致。
GUI 渲染:矩阵 → `QImage`(白底黑码,6px/模块,4 模块静区)→ `QPixmap`。

## 三、GUI 层(`gui/`)

```
┌ header   「⚡ Wlan-Flash-Transfer-V2」+ 版本号       QFrame#header
├ tabs     「服务」/「聊天」                          QTabWidget
├ 右列     二维码(QGroupBox)+ 服务日志(QPlainTextEdit)
└ statusbar 状态消息(✓ 绿 / ✗ 红)+ ⏳ 忙碌           QStatusBar
```

**服务 Tab**:

- 状态行:`chipOk/chipDim` 状态徽标(○ 已停止 / ● 启动中 / ● 运行中)+
  URL 标签(mono 蓝色,可选中)+ 复制链接 / 打开浏览器
- 配置组:端口(QLineEdit,1-65535 校验)、共享目录(+浏览)、
  **可用空间**(目录不存在时**向上探测最近存在的祖先**再 `disk_usage`,同卷容量)
- 操作行:启动服务(primary)/ 停止服务 / 打开共享目录(`QDesktopServices`)
- 共享文件表:名称/大小/修改时间,行选中,**双击行用系统默认程序打开**,
  行内「预览 / 复制」按钮(复制 = 文件本体进剪贴板,访达/资源管理器可直接粘贴),
  「删除选中」(danger 样式 + 确认框,`Worker` 后台 `unlink`)+ 刷新 + 计数
- 右列:**手机扫码直达** —— 启动后把 `url` 渲染成二维码;停止即清空

**聊天 Tab**:`QPlainTextEdit` 只读镜像,`on_chat` 信号驱动,
格式 `[HH:MM:SS] 昵称(IP): 消息`;「清空显示」只清界面不清服务端记录。

**线程模型**(原则:Qt 控件只在主线程碰):

| 场景 | 机制 |
|---|---|
| 服务日志 / 聊天回调 | `_Bridge(QObject)` 的 `log_line`/`chat_msg` 信号(子线程 emit → Qt 队列 → 主线程) |
| 启动结果 | 服务线程置位 `started` Event,主线程 `QTimer` 80ms 轮询;失败弹窗并还原 UI |
| 文件列表 / 删除 | `Worker(QThread)`,`done=pyqtSignal(object)`,异常实例统一红字提示 |
| 忙碌指示 | 主窗口 `set_busy(±1)` 计数,⏳ 标签按需显隐 |

**默认共享目录** `_default_share_dir()` = `~/Wlan-Flash-Transfer`:打包态 `__file__`
位于 .app 包内(PyInstaller 冻结目录),既不可写也不该写;固定用主目录,
开发/打包行为一致。启动服务时 `mkdir(parents=True, exist_ok=True)`,
失败弹窗拒绝启动。

**生命周期**:**关窗 ≠ 退出** —— `closeEvent` 把窗口收到系统托盘
(`QSystemTrayIcon`),服务继续运行;托盘菜单/「文件 → 退出」走 `real_quit()`
才真正 `stop_server()` 并退出(服务线程本身也是 daemon,进程退出无残留)。
首次收起有气泡提醒。托盘菜单还提供「启动/停止服务」「打开网页」快捷入口。

## 四、打包(`lan-transfer-v2.spec` / `build.sh` / `build_windows.bat`)

- 入口 `main.py`;`console=False`;图标 `assets/icon.*`(⚡ 蓝紫渐变,呼应 Web UI logo)
- **macOS 分支**:onedir + BUNDLE(`Wlan-Flash-Transfer-V2.app`,
  `com.lantransfer.gui.v2`,adhoc 签名,icns)
- **Windows 分支**:**onefile 单文件 exe**(二进制全打进 exe)——
  便于直接发给局域网内其他 Windows 机器,对方免装 Python
- **依赖快速失败守卫**:spec 顶部 `importlib.util.find_spec("PyQt6")`,
  缺失时 `raise SystemExit` 给出安装指引(含清华镜像),
  杜绝"打包成功但 exe 一跑就 `No module named 'PyQt6'`"的隐性坏包
- `build.sh` / `build_windows.bat`:检查/安装依赖 → PyInstaller →
  **frozen 冒烟**(对产物执行 `--smoke`,源码路径与 PyInstaller 冻结路径全走一遍)
- Windows exe 常见误报:未签名 PyInstaller 单文件被 SmartScreen/杀软拦截,
  选「仍要运行」;彻底解决需代码签名证书(未做)
- **产物瘦身**(spec 内 `excludes` + `_QT_DROP` 过滤):
  - `excludes` 剔除标准库(tkinter/unittest/pydoc_data 等)与 27 个未使用的
    PyQt6 模块;`a.binaries/a.datas` 按框架名过滤 QtNetwork/QtPdf/QtDBus 等
    动态库、无用插件目录与全部 `.qm` 翻译
  - macOS 分支 `strip=True` 剥符号表;Windows 不开(strip 工具缺失)、UPX 不开(杀软误报)
  - 效果:mac .app 74MB → **56MB(-24%)**
  - **两个坑**(详见 spec 注释):① conda 版 Qt 的 QtGui 硬链接 QtDBus,
    `qtdbus` 不可入过滤清单,否则冻结包 GUI 启动即崩;② 过滤按框架文件名
    (`qtnetwork`)匹配,而非模块名格式(`qt6network` 匹配不到
    `QtNetwork.framework` 路径)
  - 改过滤清单后必须 `--smoke` + `--screenshot` 双验证:
    smoke 不 import PyQt6,GUI 坏了它照样全绿

| 模式 | 命令 | 内容 |

## 六、安全模型与已知边界

**安全模型**:本工具面向**可信局域网**(家庭/测试环境),无鉴权 ——
同网段任何设备都可浏览、上传、删除共享目录内容。勿在公共 Wi-Fi 使用,
勿把共享目录指向含敏感文件的路径。

**已知边界**:

- 传输速率上限 = 路由器/网卡,与工具无关(直连 HTTP,无中转)
- 上传走单 HTTP 请求体,浏览器侧无断点续传;中断后半截文件自动清理
- 浏览器兼容下限为 2017 年内核(Chrome 55+ / Safari 10.1+):页面使用
  ES6 + async/await,但不使用可选链等 2020 后语法;更旧的内核(微信/X5
  老版本、iOS 11 等)不在支持范围
- Windows 产物需在 Windows 上打包(PyInstaller 不能跨平台),脚本已备好
- 桌面端二维码为 v2 新增(本地生成,更稳);网页端二维码弹窗保留
